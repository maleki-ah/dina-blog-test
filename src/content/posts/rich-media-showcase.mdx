Most DINA posts are plain Markdown, which keeps writing fast. When a post needs more, it becomes an `.mdx` file and can use the lab's writing components. This page is the live reference: everything below is exactly what an author writes.

## Video embeds

Talk recordings, demos and lectures are embedded with one line. The component turns a YouTube or Vimeo link into a responsive, lazy-loaded player, and keeps it LTR so it sits correctly inside Persian posts too.

```python
def fedavg(client_weights: list[list[float]], samples: list[int]) -> list[float]:
    """Weighted average of client models, weighted by sample count."""
    total = sum(samples)
    return [
        sum(n / total * w for n, w in zip(samples, dim))
        for dim in zip(*client_weights)
    ]
```

## How authors use these

- Write Markdown when a post is prose, math or a notebook.
- Switch to `.mdx` and import only the components the post needs — unused components are never shipped.
- Video, figures and tabs all stay in the post's own language and direction, so an English demo works inside the Persian site and the other way around.
